# Explainable Shipment ETA Prediction & Delay Propagation

A research prototype for the Aiqon AI/SE Intern take-home challenge. It predicts final shipment delay and the probability of exceeding a 24-hour delay threshold, while explicitly representing stage-to-stage propagation and explaining model behavior.

> **Important:** The dataset is synthetic. Results demonstrate pipeline behavior, not real-world operational accuracy. Do not use the model for live logistics decisions.

## Design choices

- **Prediction checkpoint:** after destination-port arrival and before customs clearance. Only information available by this checkpoint is used as a model feature.
- **Regression target:** final delay in hours relative to scheduled final arrival.
- **Classification target:** whether final delay exceeds 24 hours.
- **Propagation:** port processing delay depends partly on arrival delay and congestion; customs delay depends partly on customs complexity, congestion, and port-processing delay. The final delay aggregates upstream and downstream components with noise.
- **Models:** training-median baseline, Random Forest regression, Random Forest classification.
- **Explainability:** held-out permutation importance; optional SHAP summary if installed and compatible.
- **Evaluation:** held-out MAE/RMSE/R² for regression; precision/recall/F1/ROC-AUC and confusion matrix for classification.

## Setup

Python 3.10+ is recommended (3.11 tested target).

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python src/generate_data.py
python src/train_model.py
python src/explainability.py
pytest -q
streamlit run app.py
```

Run commands from the repository root. `train_model.py` writes metrics, model files, test predictions, and permutation importance under `models/`. Charts and SHAP status are written to `reports/`.

## Repository map

- `src/generate_data.py` — deterministic synthetic journey generator.
- `src/features.py` — approved features and leakage guard.
- `src/train_model.py` — split, training, evaluation, saved outputs.
- `src/explainability.py` — held-out importance and prediction plots; optional SHAP plot.
- `app.py` — Streamlit demo.
- `tests/` — reproducibility, schema, and leakage tests.
- `reports/` — charts and final report.
- `data/` — generated CSV.
- `models/` — trained models and measured metrics (generated by commands above).

## Feature and leakage policy

Features are route, distance, planned transit/port/customs durations, observed departure and port-arrival delays, weather severity, congestion, and customs complexity. The model intentionally excludes actual customs clearance timestamp, actual final arrival timestamp, realized customs delay, realized port-processing delay, and target columns. These are outcomes unavailable at the prediction checkpoint. This reduces direct target leakage.

## Limitations and next steps

1. Synthetic distributions are hand-designed and cannot establish generalization to real ports, seasons, carriers, or disruptions.
2. A random split can overestimate future performance when temporal drift exists; evaluate a chronological split when real dated data is available.
3. Feature importance describes model reliance, not causal attribution. SHAP is explanatory, not proof of causality.
4. The model does not currently produce calibrated uncertainty intervals or account for changing port schedules in real time.
5. Real deployment requires timestamped historical data, operational validation, data-quality monitoring, drift monitoring, and human oversight.

## Reproducibility

Random seeds are fixed. Always report the metrics generated by the exact code version submitted. Do not copy placeholder or expected metrics into the report; use `models/metrics.json` after running the pipeline.
